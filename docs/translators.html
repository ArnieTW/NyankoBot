Translators

Translators configure the backends used by trigger actions that translate incoming text before storing or sending the result.

Providers

Select + Add Translator, choose a backend, fill its settings, and save. Each provider card has a Test button: enter sample text, source mode, source and target languages, then select Translate before using the provider in a trigger. You can enable more than one provider.

ProviderUse it for
Google Translate API KeySimple Google v2 translation using an API key.
Google Cloud TranslationGoogle v3 translation using service-account JSON and project information.
Local TranslatorA local or self-hosted translation service that exposes compatible translate/language endpoints.

For a local provider, enter its base URL plus translate and languages paths and indicate whether it supports automatic detection. Google v2 stores an API key locally; Google v3 uses service-account JSON and project/location settings. The provider must be enabled and reachable when a trigger runs.

Trigger Actions

In Command Triggers, add Detect Language when you need the language on its own. Its Text field accepts a token such as {{text}}. Select candidate languages with the searchable multi-select, choose the minimum relative distance for a reliable result, and keep Clean chat text on when emotes or chat markup could distort detection. The default result prefix is language.

Add Translate Text to the same trigger, choose a saved Translator, enter the text and target language, then select a source-language mode. A target language is required. Language selectors show names but save normalized language codes; supported choices depend on the provider. Put this action before any chat or overlay action that reads its result.

OptionWhat it controls
DefaultUses the provider's configured source language.
Auto ProviderLets a provider with automatic detection identify the source language. The Translator test dialog calls this Auto Google for Google providers.
Auto NyankoBotUses NyankoBot's local language detector before translating.
SpecificUses the selected source language and checks reliable detection against it.
Language mismatchContinue, Skip, or Fail action when detection disagrees with a specific language or a pair is unsupported. Skip records a reason and returns no translated text.
Store result as argumentSets the output prefix, initially translation. Turn on Save as persistent when the result must survive this trigger run; Session only limits the saved value to the current session.

Use the outputs

Detect Language provides {{language.name}}, {{language.isoCode}}, {{language.confidence}}, and {{language.reliable}} by default. Translate Text provides {{translation.text}}, source and target languages, detected language, provider details, and {{translation.skipped}}/{{translation.skipReason}}. Rename either result prefix if you run the action twice. Later actions can insert these values with {{ autocomplete.

Example: detect {{text}}, translate it to Japanese, then add Send Chat Message with {{translation.text}}. If the output is empty, check the provider test, language pair, and skip reason in trigger History.
