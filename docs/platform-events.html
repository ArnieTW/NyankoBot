Triggers

Platform Events

NyankoBot can start a command trigger or overlay binding from connected platform events. The picker lists implemented events from enabled connectors. Receiving an event also depends on the connection, login permissions, and subscriptions.

Choose the right event

  1. Connect the platform under Connectors and enable the event subscriptions required by that connector.
  2. Open Command Triggers, add a trigger, and add the desired event under its Triggers section. Search by name or category.
  3. Set any source-specific filters or hit rules. Add permissions and cooldowns for user-driven commands, then add actions if the event should do more than activate an overlay.
  4. Save the Command Trigger. To show content, open an overlay Binding Editor and attach the saved trigger in its Command Trigger picker tab.
  5. Cause a real event and review trigger History if it does not run.

Use a NyankoBot Channel Reward binding for a shared reward definition. Use a generic Twitch Channel Points event for a platform reward lifecycle event or a reward that NyankoBot does not manage.

Ad Notification fires before the next scheduled ad using the lead time configured on that trigger source; the initial lead time is 10 minutes. It depends on Twitch schedule data being available to the connector.

Which Twitch event should I choose?

For a new follow or cheer, choose Follow or Cheer. For subscription messages, choose the matching new, renewed, gifted, or ended event. For Channel Points, choose redemption added versus redemption updated according to whether you need the initial request or its later status. For stream start and stop, use StreamOnline and StreamOffline; StreamUpdate is for metadata changes.

For ads, AdBreakBegin reacts when a break starts. AdNotification reacts before a scheduled break; set its minutes-before-ad value on the trigger source. Goals and Hype Trains have begin, progress, and end variants. Shoutouts have sent and received variants. Guest Star exposes session, guest, and settings updates. Poll and prediction event definitions are currently marked unimplemented, although poll and prediction connector actions are available.

Kick, OBS, Streamer.bot, and NyankoBot

  • Kick: chat messages, commands, first words, and stream online/offline/metadata events.
  • OBS: events from the connected OBS WebSocket session.
  • Streamer.bot: subscribed raw events, commands, and action triggers. See Streamer.bot Connector.
  • NyankoBot: synthetic commands, first words, timers, manual triggers, and Stream Deck calls.

Kick currently exposes chat messages, commands, first words, and stream online/offline/metadata updates in the trigger picker. Other webhook and chat event definitions exist in source but are marked unimplemented and do not appear as selectable trigger sources. Chat needs the chat connection; stream status events need the connector's stream monitor.

If an expected event is missing, check connector health and subscriptions first. A selected event cannot fire until its source connector is enabled and receiving it.
