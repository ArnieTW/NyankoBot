Settings and Storage

Variables

A variable definition describes a value's name, scope, type, shape, and default. Storage shows where that value is used and, for persistent variables, its current runtime value.

Define a variable

  1. Open Settings → Variables and select Add variable.
  2. Enter a name and choose Argument for a value used during a trigger run or Persistent for a value kept across runs.
  3. Choose a type: String, Number, Boolean, Date, JSON, or Object / Class. Choose Single, List, or Dictionary for its shape.
  4. Set a default. Lists and dictionaries use JSON defaults; Object / Class exposes named properties and property defaults. Persistent definitions can enable Clear runtime value when NyankoBot starts.
  5. Select Save variable. You can filter and reopen saved definitions to edit them.

Deleting a definition leaves trigger actions that reference it unable to change that variable. Review its usage first in Storage.

Inspect and edit values

  1. Open Storage → Variables.
  2. Filter by name or choose All, Persistent only, Season only, or Arguments only.
  3. Select a variable. Assigned and used by lists saved triggers that write or reference it.
  4. Review the default and, for a persistent variable, the current stored value. Edit them and select Save values.

When no persistent value has been stored, runtime reads fall back to the default. An argument has no current value outside the trigger run that creates it. Structured values must match their JSON list, object, or dictionary shape.

Use variables in trigger actions

In Command Triggers, add Set Argument or Set Persistent Variable to change a defined value. Those actions expose variable operations appropriate to the definition's type and shape. Later actions can use values produced by earlier actions through token autocomplete.

Select String, Detect Language, Translate Text, HTTP requests, and connector requests can also produce arguments. See the Action Reference for the action catalog and result handling.
