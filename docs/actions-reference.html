Command Triggers

Action Reference

Actions run when a command trigger passes its event, permission, and cooldown checks. Open a trigger, select Add Action, choose the action, fill its fields, then save the trigger.

Connector Request is the internal runner for connector-specific actions. The Add Action picker shows each implemented request by its own name. IF Statement appears as a rule in the action flow. Both are included below because saved actions use those types.

Send Chat Message

Enter the message and select one or more Platform targets. Return to triggered platform sends to the event's originating connection first; if that send fails, the action tries the other selected targets. A blank target selection also uses the triggered platform. Tokens such as {{user.display}} and {{text}} are resolved when the action runs.

Send as Bot chooses the bot account. Fallback to Broadcaster allows the broadcaster account when bot sending is unavailable. An empty resolved message sends nothing. This action posts chat rather than creating a result argument; check the connector and logs if the message does not appear.

Set Argument, Set Persistent Variable, and Select String

Set Argument

Select or create an Argument definition, then add one or more ordered operations. The action starts with the value already present in this trigger run or with the definition's default. The final value is available to later actions as {{variableName}}. Argument values are scoped to the run.

Set Persistent Variable

Select or create a Persistent definition and add operations. The action starts with the stored value or the default, applies operations in order, and saves the result. The definition controls whether the stored value is session-only. Inspect it later under Storage → Variables.

The operation menu changes with the definition's type and shape. It includes set/reset; number arithmetic and bounds; text append/prepend/replace; date and Boolean changes; and list, dictionary, or object edits. Collection selectors can target one or several entries. Find, Exists, and Count can store a query result under an argument name for the next action.

Select String

Enter an Argument name and one choice per line under Strings. Choose Sequence to advance through choices, Random to select randomly, or Custom to use IF/Else rules. Tokens inside the selected string are resolved at run time. A later action reads the choice as {{argumentName}}. An empty name or list produces no value.

Detect Language and Translate Text

Detect Language

Set Text to a literal or token such as {{text}}. Narrow Candidate languages when the expected languages are known. Minimum distance controls how strongly one result must lead the others (0 to 0.99); Clean chat text removes chat noise before detection. The default result prefix is language.

Later actions can read {{language.name}}, {{language.isoCode}}, {{language.confidence}}, and {{language.reliable}}. Change Result token prefix when a flow performs more than one detection.

Translate Text

Choose a saved Translator, enter Text and a required Target language, then choose Default, Specific, Auto Provider, or Auto NyankoBot source mode. Specific shows a source-language selector. Language mismatch can Continue, Skip, or Fail action. Clean chat text for detection affects language detection.

Store result as argument defaults to translation. The action sets {{translation.text}} and source, target, detected-language, provider, skipped, and skip-reason fields. Save as persistent also stores the result; Session only limits that stored result to the current session. See Translators for a full setup example.

Wait and IF Statement

Wait

Set Delay (ms) to pause the flow before the next action. The editor accepts 10 through 86,400,000 milliseconds; 1000 is one second. It creates no result token.

IF Statement

Add a rule to compare a left value, operator, and right value. Put actions under THEN; add ELSE IF branches for more comparisons and ELSE for unmatched events. Only the first matching branch runs. These are nested actions, so their output can feed later actions in the same flow. See IF/Else Control for operators and rule editing.

Action rows also support their own conditions. A row whose condition does not match is skipped. Enabled actions run in saved order. If an action throws an error, NyankoBot logs it and continues evaluating later actions unless the flow explicitly stops.

Trigger Binding and Trigger Box Source

Trigger Binding

Select the Overlay, optionally a Box, and the required Binding. This invokes that binding with the current trigger data, so its items and sequencing run as configured. The action exposes its fired count under an action-specific actions.<action-id>.overlayBinding.firedCount mapping.

Trigger Box Source

Select an Overlay and Box, then choose an existing source variation or configure a manual source using the source editor. Set Timing to Max Length, Toggle, or a custom duration. This fires the selected source directly instead of choosing through a binding's sequence. Its fired count is available as actions.<action-id>.overlayBoxSource.firedCount.

HTTP Request and Discord Webhook

HTTP Request

Choose GET, POST, PUT, PATCH, or DELETE; enter a token-aware URL; and select no authentication, a bearer token, or an API key in a header or query string. Optional headers use one Name: value line each. For methods other than GET, enter a body and content type. The default content type is application/json.

Optionally set Store result as argument. NyankoBot parses a JSON response when possible and stores it under that name, plus .response and .statusCode. Save as persistent and Session only control longer-lived storage. Fail action on HTTP error is on by default; turn it off only when the flow should handle an error response itself.

Discord Webhook

Enter the webhook URL and message. Optional fields override the posted username and avatar URL. Embeds JSON accepts an object or array of Discord embed objects; tokens are resolved before parsing. Fail action on Discord error is on by default. The action reports an HTTP status in its action-specific mapping but does not create a named result argument.

Connector-specific requests

Choose an implemented Twitch, Kick, OBS, or Streamer.bot request by name in the Add Action picker. The selected request supplies its own fields and filters the connector list to compatible instances. Fill the required fields shown there. Some requests require platform account scopes or broadcaster/moderator permission. The generic Connector Request type stores the selection and payload but is not a standalone picker choice.

Set Store result as argument when another action needs the connector response. Save as persistent and Session only control longer-lived storage. Use the Connector Action Catalog for every implemented Twitch and Kick request in the current source catalog; OBS requests come from its connected functionality catalog and Streamer.bot currently contributes Send chat message.

Build a flow

  1. Create or open a Command Trigger and add the event that should start it.
  2. Add actions in the order they should run. Use IF Statement for branches and Wait for a timed pause.
  3. For a variable action, create its definition first under Settings → Variables.
  4. For translation, configure a provider under Translators. For a connector request, connect the required platform under Connectors.
  5. Save and test the trigger, then inspect History for matched events, inputs, and action results.

Results and tokens

Fields with token autocomplete can read the incoming event, for example {{user.display}} or {{text}}. An action can also use arguments and results produced by actions before it. Put a producer action before the action that reads its output.

For example, Detect Language with the default result prefix supplies {{language.isoCode}}, {{language.confidence}}, and {{language.reliable}}. Translate Text with the default prefix supplies {{translation.text}}, {{translation.sourceLanguage}}, {{translation.targetLanguage}}, and skip information. An HTTP Request with a chosen result name also exposes its .response and .statusCode fields. Rename the prefix in the action when a flow needs more than one result of the same kind.

Use Trigger tokens for common event and connector-scoped mappings. The action editor's fields are generated from each action's schema, so select an action to see its exact required inputs and available result storage options.
